### 如何复验

本地浏览器验收后补齐了目标 Doris 验收工具与[放行手册](Doris试点放行手册.md)。四个冻结用例离线编译通过；新增 7 项工具回归，使用实际 Doris 适配器和模拟 socket，覆盖版本不符、预检阻断、参考值不符和模拟断连。当前 `npm run check`、`npm test`（296/296，17 个套件）及 `git diff --check` 均通过。

```sh
npm run check
npm test
git diff --check
node --import tsx tests/fixtures/serve-frozen-business.ts
```

夹具只监听 `127.0.0.1:18763`。按终端输出在本地工作台登录，打开「支付订单 · 冻结验收」会话的「结果」页签，用 `/__fixture` 确认操作前后差值。三份预生成报告共用指标：两日仅总量（2 行）、两日含渠道（8 行）、十日含渠道（40 行）。打开 11-20 的广告投放抽屉，分别点 90 和 165，核对行、SQL 和执行时间。回到只有总数的报告，打开补查表单（应不回源），选择渠道并确认（应新增一个 SELECT 和独立结果 ID）。用十日夹具缩放至最后两日，分别在 1440px 和 390px 视口检查键盘操作、切图和实际下载的 SVG／PNG。

### 如何读旧版基线

2026-11-19 至 11-20 的 17 条历史任务合计 111 次工具调用、30 次失败。两条含读 `stream` 异常的轨迹，在首次异常后又分别启动 5 次、3 次源工具。历史事件没有驱动级 dispatch 记录，**不能把这 8 次等同于源库请求，也不能和新版模拟回放推算生产改善率**。单次故障、并发断连和历史结果派生回放可作为固定回归；冻结样例的 340 与 70 是语义对照，不是延迟基准。

## 暂不扩围

- 需要在目标 Doris 版本用实际授权和只读账户复核 `stream` 故障、模板方言、预检、时区和成本。按[放行手册](Doris试点放行手册.md)先离线编译、再读 EXPLAIN、审批后查冻结快照。当前 Doris 文本 EXPLAIN 无可用成本估算，`enforce` 会阻断未知估算；`warn` 兼容检查不代表通过正式成本策略。尚未在目标版本复现历史故障，不能宣称真实故障已修复。
- 目前模板支持选定的明细计数、求和、去重、比率、当前维度和订单级双事实净额；不支持事件时点维表或任意多对多／分摊。目录索引覆盖已发布的业务域，不代表自动索引全库；结构化定义与关系摘要需人工签认。
- 待真实数据负责人确认首批表、指标、关系和水位，并提供独立参考答案。以相同模型、预算、时区、权限及冻结数据做新旧对照：50 道脱敏题，每题每版至少 3 次。统计可回答题正确率、错误标为已核验数、首条业务 SQL 可执行率、首个可核验答案 P90，以及断连和复用后的驱动 dispatch。对照完成前，不宣称正确率 ≥95%、高风险误核验为零或 P90 下降 ≥40%。
- 已完成本机 Chromium 桌面及 390px 移动视口复验；未做实体手机跨设备验证，也没有 5 人试用记录，不宣称达到查找时间／点击数门槛。

回切时关闭该连接的试点开关；新请求走探索流程，已有业务报告保留其原始定义、数据范围和证据。发布新版本不会自动启用，也不会用新公式改写旧结果。
