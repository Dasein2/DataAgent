# 分析回答与等待体验验收

## 本版实现

1. **问题驱动的分析深度**：数值问题只做所需计算和必要核对；趋势、分布、对比只分析请求的维度；原因问题区分可验证驱动与因果限制。已有证据足够就收敛，不为丰富报告继续查数据。不是每道题固定执行一套工具清单。
2. **先探索、后按需追问**：允许先获取相关定义、结构和有界样例；无法确定且影响结果的选择用 `ask_user`。明确问题不例行确认。保留自由文本纠正、同任务恢复和累计预算。
3. **答案与依据分层**：模型完成的一条非工具回复通过 `answer_ready` 提前展示，仍由 `task_finished` 决定最终状态；不是把中间查询预览当答案。答案在执行记录前，SQL 和数据依据默认折叠，正文中的限制不被自动隐藏。不完整答案有显式标签。历史会话同样分层。
4. **等待状态卡**：发送时立即出现，显示事件驱动的阶段、累计执行耗时、取消入口；追问时暂停计时和动画；长查询不显示虚构比例。断线保留任务，SSE 按 cursor 恢复并去重，轮询补齐终态或待答问题。

专业性来自统计粒度、时间边界、去重/关联基数、覆盖范围及证据引用；不是 SQL 数量或长报告。

## 自动回归覆盖

- `tests/grounded-clarification.test.ts`：四类连接能力下先查结构和样例再问，纠正应用到 SQL，恢复不重复探索，清晰追问直接完成。使用 PGlite + 模拟模型，不等于四种真实数据库的全量集成。
- `tests/answer-experience.test.ts`：状态卡立即显示、长查询、累计执行计时、用户等待冻结、断线/恢复、取消、重复事件、SQL 分离、重要限制保留、依据链接。
- `tests/answer-ready.test.ts`：只在模型完整回答时发布答案就绪，先于证据整理完成；工具预览和计划不触发。
- `tests/task-stream.test.ts`：断流 cursor、重复抑制、静默连接超时、轮询终态/追问、切换会话取消重连。
- `tests/task-activity.test.ts`、`tests/console-layout.test.ts`：答案不重复、先于技术历史、过程默认折叠、历史懒加载、自由文本与选择去重提交。
- 本地 PostgreSQL wire 集成验证真实读取、只读边界、元数据和预算；PGlite 不支持的真实控制连接取消用例跳过，MySQL 需另行提供测试连接。

## 可复跑的真实模型验收

```bash
npm run eval:experience -- --env-file .env.e2e --pi-provider "国产-envision" --pi-model deepseek-flash
# 单题复测，不必重跑全套
npm run eval:experience -- --env-file .env.e2e --pi-provider "国产-envision" --pi-model deepseek-v4.1-flash-1017 --case clarification --output .tmp/experience-clarification.json
```

脚本建立临时数据库和隔离数据目录，不使用生产连接。指定 Pi 渠道时，仅用该渠道自己的凭证和地址，不沿用 `.env.e2e` 的模型密钥，也不会更改项目默认模型。验收先探测模型连通性，`--case` 可指定单题；执行失败或基本验收规则不满足时返回非零。四题如下：

| 场景 | 正确行为 |
| --- | --- |
| sales 订单数 | 10 笔，明确一行一单；不追问、不制图、不扩展建议 |
| 按 region 金额分布 | US 最高 560.74；一张柱状图、必要结论和可查证据 |
| orders 一月订单数 | 发现下单/支付时间差异后带依据追问；输入支付时间且仅已支付后为 2 笔 |
| 汇总日活下降原因 | 100 到 80，下降 20 / 20%；只有汇总数据，不能证明原因，不编造归因 |

输出记录：任务状态、模型、答案原文/长度、问题与回答、SQL/结果、调用列表、查询/轮次、执行与等待耗时、`answer_ready` 到达时间。**首个服务端事件时间不是 UI 响应时间，`answer_ready` 时间也不等于独立核验正确性的时间。** 人工对照结果核验后才能评价回答质量。没有旧版同配置对照时不能声称提速百分比。

### 本次真实模型尝试（2026-11-25）

根据要求，正式复测使用 Pi 配置的「国产-envision」DS 渠道，不使用 `.env.e2e` 的官方 DeepSeek 密钥。类型检查、构建和 319 项本地回归通过；PostgreSQL wire 集成 11 项通过，1 项取消测试因 PGlite 限制跳过。

- `deepseek-flash` 最后一轮：订单数 10 笔（答案就绪约 6.6 秒）；分布题一张图、US 560.74（9.0 秒）；原因题确认下降 20%，明确不能归因（13.0 秒）。三题通过基本检查。
- 口径题会说明下单时间与支付时间的差异，并在确认后查出 2 笔。但 `deepseek-flash` 仍先按下单时间做了一次分组计数，且正文首句一度将「支付时间」误写为「下单时间」，与 SQL 不一致。`deepseek-v4.1-flash-1017` 两次单题复测正文和 SQL 一致，答案约 18–19 秒就绪，但强化有界采样指引后，最新一轮仍在追问前多做了一次状态聚合。**严格的「有限探查、先澄清再计算」路由验收没有通过。** 目标不是禁用追问前查库，而是用元数据或有界样例代替无关计数。
- 原始记录：`.tmp/answer-experience-pi-eval-r4.json`、`.tmp/answer-experience-pi-v41-bounded.json`（本地忽略文件）。耗时是隔离环境中本次实际模型运行，不是线上提速结论。

## 仍需环境验收

- 后续重点复核口径题两点：是否只做必要探查后就追问，最终正文写明的统计口径是否与实际 SQL 一致。仅凭任务 `succeeded` 或答案数字正确，不算验收通过。
- 前次线上四条任务不在本次隔离 fixture 中；要做同题前后对照，必须在获准的测试环境重放，固定模型/资料/预算/数据快照，并记录首次可核对答案时间。
- 本次没有操作浏览器，也没有部署线上。DOM 回归不替代桌面、窄屏、深浅主题、可访问性及实际网络条件下的浏览器验收。
- 提示词规则约束模型行为，但不能机械证明每次回复都简洁或查询数最少；不得把文字截断或省略关键核对当作优化。
