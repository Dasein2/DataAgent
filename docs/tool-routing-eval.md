# 模型工具路由 A/B 验收

本页定义评测用例和判定标准，不是实测结果。单元测试、SDK 请求检查和数据库集成测试能确认实现正确，不能证明模型更少误选工具。

## 对照设置

- A：旧版 24 个模型工具与旧提示词；B：合并重复工具后的版本，管理工具始终可用，工作区与执行计划工具按能力提供。
- 固定模型版本、推理设置、预算、预检模式、时区（UTC）、连接能力与业务上下文。使用隔离数据目录和同一份 `scripts/seed/postgres.sql` 或 PGlite fixture，不在生产库评测。
- 每个用例开新会话。标记「前置」的先准备并确认同样的数据，再提交目标；只从目标开始计量。每组至少重复 3 次；用事实和证据评分，不按是否逐字采用建议的工具链评分。

## 用例

| # | 给模型的任务 / 前置条件 | 判定 |
| --- | --- | --- |
| 1 | “找名字含 sales 的表或视图，只列候选，不查业务数据。” | 找到 `public.sales`、`public.sales_by_region`；简单查找无需 `catalog_overview` 或采样。 |
| 2 | “概览 public 中的业务表、时间字段和已声明的关联，只看元数据。” | 有界结构概览；识别 `created_at`，不把推测当作声明外键；不执行源 SELECT 读业务行。 |
| 3 | “同时描述 public.sales、public.sales_by_region 和 public.missing_table；找不到也继续。” | 前两个给出正确结构，缺失项单独说明；新版可一次 `object_describe(objects)` 完成。 |
| 4 | “用默认采样看看 region 和 amount 的空值和范围。” | `data_profile` 或等价有界采样，披露样本范围；不把样本统计当成总体统计。 |
| 5 | 前置：已保存完整的 `id, region, amount`，按 id 升序。目标：“只看已保存结果的头两行，给出 region 和 amount。” | 两行是 EU 120.50、EU 80.00；读行或使用已有预览，不重新查询。 |
| 6 | 前置：同上。目标：“统计这个已保存结果中 region 的去重数和 amount 的空值数。” | 4、0，注明范围是已保存的 10 行；不用源库、不把所有行翻进上下文。 |
| 7 | 前置：同上。目标：“基于已有结果算各区总金额，报第一名，并生成柱状图。” | 本地聚合后制图；US 精确金额 560.74，引用可解析，派生结果指向父结果；无回源。 |
| 8 | 前置：把上述完整结果命名为 baseline。目标：“用 baseline 快照统计 APAC 的总金额，不要刷新。” | 485.20，通过快照或其指向的已验证结果进行本地分析；无回源，lineage 指回原结果。 |
| 9 | 前置：只保存 `region, amount`。目标：“各区退款率是多少？分母为该区全部订单。” | 缺少 `refunded` 时查源；LATAM 50%、EU 和 US 各 1/3、APAC 0%；不臆测缺列值。 |
| 10 | 前置：查询行数上限强制只保存头两行，且有截断标记。目标：“给出全表按 region 的总金额。” | 源库执行聚合，不在两行上计算全表结果；APAC 485.20、EU 440.60、LATAM 245.40、US 560.74。 |
| 11 | 前置：保存 `COUNT(*)=10` 后由 fixture 管理连接增加一行。目标：“重新查现在的订单笔数。” | 11，并用新的源查询证据；不能打开 `reuse` 或拿旧结果冒充最新。每次重放后恢复 fixture。 |
| 12 | 前置：生产视图权限的测试 workspace。目标：“建一个 `ds_region_totals` 视图，供后续源库 SQL 引用，并验证它能查到数据。” | `dataset_create` 建视图，后续源 SQL 引用它；不直接发送 DDL。无工作区的复测要如实说明、不给成功结论，仍能提供不落库的替代结果。 |
| 13 | 前置：使用无 EXPLAIN 能力的测试连接或模拟探针。目标：“只看查询计划，不实际执行查询。” | 明确计划不可用，不调用未注册工具、不把实际执行当成计划。用 `/v1/tools?session_id=…` 和模型请求确认 `query_explain` 未暴露。 |
| 14 | 前置：同一会话已经生成一张图。目标：“把刚才那张图改名为『按地区销售额』。” | 不需要切换模式。`chart_revise` 创建新版本，旧图及引用仍有效；不擅自归档旧图，不回源。普通分析用例不应主动归档、改名或取消 SQL。 |

## 记录与通过标准

- 保存 `GET /v1/tasks/{id}` 的状态、答案、`queries_used` 和 `/events`；用 `tool_started`/`tool_finished` 追踪调用和错误。单独记录元数据调用、源数据 SELECT、EXPLAIN/预检、本地派生、workspace 操作次数。`queries_used` 是预算计数，不是所有源库请求的计数。
- 检查引用、原始 SQL、截断标记及 lineage。把不可用工具、错误参数、对充足的本地数据无谓回源及相应重试记为路由问题；不要把合理改写或预检失败都归为误选。
- 优先要求结论与证据不退化、权限边界不变，再比较源库查询和误选重试。报告各用例数据和失败，不用工具数量代替效果数据。
