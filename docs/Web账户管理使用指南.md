# 🎉 Web 账户管理系统 - 使用指南

## 快速访问

1. **启动应用**
   ```bash
   npm run build
   npm start
   ```

2. **先登录控制台**
   - 在运行服务的电脑上打开 <http://127.0.0.1:8787/>，使用管理员账户登录。首次初始化的管理员用户名为 `admin`，请使用当前密码。
3. **在同一浏览器、同一域名下打开账户管理**
   - <http://127.0.0.1:8787/accounts>
   - `8787` 是默认端口；如设置了 `DATA_AGENT_PORT`，使用启动日志中的端口。服务器部署后，使用实际对外的 HTTPS 域名，例如 `https://your-domain.example/accounts`。

## 功能概览

### ✅ 已实现的功能

#### 1. 创建账户
- **位置**：左侧面板 "创建新账户"
- **支持角色**：
  - 👤 普通用户：可以进行数据分析，不能修改系统配置
  - 👑 管理员：拥有所有权限，可以管理模型和系统设置
- **密码要求**：至少 8 个字符
- **用户名规则**：只能包含字母、数字、点(.)、下划线(_)、连字符(-)

#### 2. 查看账户列表
- **显示信息**：
  - 用户名
  - 角色（管理员/普通用户）
  - 活跃会话数
  - 操作按钮
- **自动刷新**：创建、删除、重置密码后自动刷新列表

#### 3. 重置密码
- **操作**：点击账户列表中的 "重置密码" 按钮
- **效果**：
  - 立即更新密码
  - 使该用户的所有活跃会话失效
  - 用户需要使用新密码重新登录

#### 4. 删除账户
- **操作**：点击账户列表中的 "删除" 按钮
- **限制**：
  - 无法删除自己的账户
  - 无法删除最后一个管理员账户
- **效果**：
  - 删除账户本身
  - 删除所有活跃会话
  - 用户的历史数据仍保留在文件系统中

## API 端点（供开发者参考）

### 账户管理 API（仅管理员）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v1/auth/accounts` | 列出所有账户 |
| POST | `/v1/auth/accounts` | 创建新账户 |
| POST | `/v1/auth/accounts/:username/reset-password` | 重置密码 |
| DELETE | `/v1/auth/accounts/:username` | 删除账户 |

### 创建账户示例

```bash
curl -X POST http://127.0.0.1:8787/v1/auth/accounts \
  -H "Content-Type: application/json" \
  -d '{
    "username": "alice",
    "password": "SecurePassword123",
    "role": "user"
  }'
```

### 重置密码示例

```bash
curl -X POST http://127.0.0.1:8787/v1/auth/accounts/alice/reset-password \
  -H "Content-Type: application/json" \
  -d '{
    "password": "NewSecurePassword456"
  }'
```

### 删除账户示例

```bash
curl -X DELETE http://127.0.0.1:8787/v1/auth/accounts/alice
```

## 使用流程示例

### 场景 1：为团队添加新成员

1. 管理员访问 http://127.0.0.1:8787/accounts
2. 在左侧 "创建新账户" 表单中输入：
   - 用户名: `alice`
   - 密码: `SecurePassword123`
   - 角色: `普通用户`
3. 点击 "创建账户"
4. 页面显示成功消息，右侧列表自动刷新
5. 将用户名和密码告知新成员
6. 新成员访问 http://127.0.0.1:8787 并登录

### 场景 2：用户忘记密码

1. 管理员访问账户管理页面
2. 在账户列表中找到该用户
3. 点击 "重置密码" 按钮
4. 输入新密码（至少8个字符）
5. 点击 "重置"
6. 系统自动使该用户的所有会话失效
7. 将新密码告知用户
8. 用户使用新密码重新登录

### 场景 3：员工离职，删除账户

1. 管理员访问账户管理页面
2. 在账户列表中找到该用户
3. 点击 "删除" 按钮
4. 在确认对话框中点击 "删除"
5. 账户立即被删除，所有会话失效
6. 用户的历史数据仍保留（如需删除，需手动清理）

## 安全特性

### ✅ 已实现

- **权限检查**：只有管理员可以访问账户管理页面
- **CSRF 防护**：所有写操作都检查同源
- **Session 验证**：每个请求都验证登录状态
- **密码强度**：强制要求至少 8 个字符
- **操作确认**：删除账户需要二次确认
- **自动登出**：密码重置后使所有会话失效

### 🔒 权限隔离

- **管理员**：
  - ✅ 管理账户
  - ✅ 修改模型配置
  - ✅ 管理提供商
  - ✅ 所有数据分析功能

- **普通用户**：
  - ✅ 数据库连接
  - ✅ 执行查询
  - ✅ 创建图表
  - ✅ 管理自己的业务上下文
  - ❌ 不能访问账户管理
  - ❌ 不能修改模型配置

## 注意事项

### ⚠️ 重要提示

1. **首次登录后修改密码**
   - 环境变量中的 `DATA_AGENT_ADMIN_PASSWORD` 只在初始化时使用
   - 建议首次登录后立即修改密码

2. **不能删除最后一个管理员**
   - 系统至少需要保留一个管理员账户
   - 如果要删除当前唯一的管理员，先创建另一个管理员

3. **不能删除自己的账户**
   - 登录用户不能删除自己的账户
   - 需要由其他管理员操作

4. **历史数据保留**
   - 删除账户不会删除该用户的历史数据
   - 会话记录、查询结果等仍保留在 `data/history/` 中
   - 如需完全清理，需要手动删除对应 ownerKey 的文件

5. **密码重置影响**
   - 重置密码会使该用户的所有活跃会话失效
   - 用户需要使用新密码重新登录
   - 建议通过安全渠道传递新密码

## 故障排查

### 问题 1：无法访问账户管理页面

**症状**：访问 /accounts 显示 "只有管理员可以访问此页面"

**原因**：当前登录用户不是管理员

**解决**：
1. 登出当前账户
2. 使用管理员账户登录（默认是 admin）

### 问题 2：创建账户失败 - 用户名已存在

**症状**：点击 "创建账户" 后显示 "用户名已存在"

**解决**：
1. 使用不同的用户名
2. 或先删除同名的旧账户

### 问题 3：密码太短

**症状**：输入密码后提示 "密码太短"

**解决**：确保密码至少包含 8 个字符

### 问题 4：无法删除账户

**症状**：点击删除按钮后提示 "无法删除最后一个管理员"

**解决**：
1. 先创建另一个管理员账户
2. 然后再删除当前管理员

## 与命令行工具的对比

| 功能 | Web 界面 | 命令行工具 |
|------|---------|-----------|
| **便捷性** | ✅ 浏览器访问，无需 SSH | ❌ 需要 SSH 到服务器 |
| **图形化** | ✅ 直观的界面 | ❌ 纯文本输出 |
| **实时更新** | ✅ 自动刷新列表 | ❌ 需要重新运行命令 |
| **权限控制** | ✅ 只有管理员可访问 | ❌ 需要服务器访问权限 |
| **批量操作** | ❌ 需要逐个操作 | ✅ 可以脚本化 |
| **生产环境** | ✅ 推荐使用 | ⚠️ 不推荐（需要服务器访问） |

**推荐**：生产环境使用 Web 界面，开发环境可以使用命令行工具。
