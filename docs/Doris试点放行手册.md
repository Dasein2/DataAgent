# Doris 试点放行手册

> 历史试点记录。工作台已移除业务目录、签认发布和灰度入口。独立 Doris 兼容性检查脚本仍可用于复验历史用例。

当前状态：**待目标环境验收，未开启正式灰度**。下列工具只做兼容性检查，不替代业务签认、新旧 A/B 或正式放行。旧版对照基线为 `49dd038`；本地证据见[试点交付与验收记录](数据分析Agent试点验收.md)。

## 1. 上线前先备齐三样材料

| 责任人 | 交付材料 |
|---|---|
| Doris 管理员 | 获批的隔离非生产实例、目标构建号（FE 和 BE）、可核对的冻结快照编号、经批准的查询配额和运行窗口；给指定库或对象直接授予 `SELECT` 的测试账号，不用角色继承、管理员或写账号。确认地址、TLS／SSH 路径和账号确实指向测试实例。 |
| 数据负责人 | 首个业务域的表粒度、复合键、时间存储、时区、覆盖水位及指标／关系定义；对字段和关系逐项签认。用独立 SQL 或手算核对参考值，不拿模板或旧版输出当标准。记录参考答案的版本及引用。 |
| 验收负责人 | 冻结两版提交和环境配置，准备 50 道脱敏题及评分标准；记录目标环境预检策略、可接受扫描量和超时上限。只允许对已复核的有界快照执行测试。 |

不要把账号密码、内网地址、原始业务数据或未脱敏日志粘贴到聊天、工单正文或提交。目标文件保存在仓库外，仅向执行人开放；不用应用现有连接、`.env`、保存的连接或生产凭据。`environment: non_production` 和授权编号是执行人声明，不能凭它们识别生产库。`@@version_comment` 核对的是当前 FE；节点版本一致性及快照内容仍需管理员确认。Doris 的 [`VERSION()`](https://doris.apache.org/docs/4.x/sql-manual/sql-functions/scalar-functions/system-functions/version-function/) 可能只返回兼容值 `5.7.99`，不能用它确认构建号。

## 2. 兼容性检查：先离线，再执行计划，最后查快照

**本地无需账号或网络：**

```sh
node --import tsx scripts/doris-pilot-check.ts tests/fixtures/doris-pilot-cases.json
node --import tsx --test tests/doris-pilot-check.test.ts
```

样例清单只用于展示结构和验证工具本身。四个用例覆盖净收款 70 元（100 − 10 − 20）、支付单量 450 → 360 及渠道差额、UTC→上海时区半开日界、缺日不补零。回归使用实际 `DbSession` / `DorisEngine` 和模拟 socket，SQL 由 PGlite 适配执行，**没有验证真实 Doris 方言、优化器或 mysql2 网络行为**。

**获批后**，复制样例结构填写脱敏 `MANIFEST.json`：填快照号、独立参考答案引用、目录定义及最多 20 个兼容性用例。日期按业务时区、右边界不含；逐日填期内总数、基期、差值，缺失用 `null`，需要时额外填渠道或操作数。精确数值用 JSON 字符串。加入实际发布范围内的模板，并覆盖至少一项不应核验的反例；一次输入只包含一个数据库。离线先校验编译和 SQL guard，记录 `manifest_sha256` 与各题 `sql_sha256`（内容标识，不证明数据一致）。

仓库外的 `PRIVATE_TARGET.json` 格式（均为占位值）：

```json
{
  "authorization_ref": "批准记录编号",
  "snapshot_ref": "与清单一致的冻结快照编号",
  "version_comment": "doris version <获批的完整 @@version_comment>",
  "connection": {
    "engine": "doris",
    "environment": "non_production",
    "host": "approved-test-host.example.invalid",
    "port": 9030,
    "database": "与清单一致的库名",
    "user": "测试只读账号",
    "password": "仅在本地填入"
  }
}
```

连接可使用项目已有的 `ssl`／`ssh` 配置，不要绕过服务器证书或主机密钥校验。脚本拒绝生产声明、弱只读、配置工作区或快照编号不一致；连接后未通过账号授权或精确构建匹配不读业务表。目录草稿、发布和启用只发生在临时 SQLite，关闭后清理，不接触现有服务的灰度开关，也不调用模型。

```sh
# 先看文本计划和 enforce 判定：版本探针是 SELECT，但不执行任何业务 SELECT
node --import tsx scripts/doris-pilot-check.ts MANIFEST.json --plan PRIVATE_TARGET.json > plan.json
# 仅在计划、分区范围及扫描量经 DBA 复核批准后，显式运行 warn 兼容性检查
node --import tsx scripts/doris-pilot-check.ts MANIFEST.json --smoke PRIVATE_TARGET.json > smoke.json
```

- `--plan` 每题调用一次应用预检（`policy`）及一次普通 `EXPLAIN`（文本计划）；**不使用 `EXPLAIN ANALYZE`**。当前 Doris 适配器不解析文本计划的扫描行数／成本，`enforce` 对未知估算返回 `blocked: true`。这是策略行为，不是成本达标。正式环境如要求 `enforce`，仍被此限制拦截；不要用 `--smoke` 的成功结果放行。
- `--smoke` 每题先跑普通 `EXPLAIN`，成功才走应用 `warn` 预检和结构化分析；任一计划请求失败都阻断该题的业务 SELECT。限制每次业务 SQL 最长 15 秒、最多 2,000 行、4 MB。`LIMIT`、输出上限和超时不限制实际扫描量。匹配独立参考值、状态及保存结果的操作数引用，每题应恰好 1 次业务 SELECT。错误、截断、对账不符或额外 dispatch 均不通过；失效后停止后续用例，不重放。
- 输出 `setup` 和逐题 `requests`／`operations` 分开；setup 包含版本 probe 与目录校验，不含连接建立和 `DbSession.open` 初始化探针。计划模式的额外 `EXPLAIN` 是验收开销，不算 Agent 的线上预检成本。`select_ms` 是执行／取数计时，不是首个可核验答案延迟。`result_id` 只供该次检查关联证据，临时结果结束后不可重开。计划可能含表名和过滤值；把输出保存在受限位置，只传脱敏摘要。
- 检查 `ok`、逐题差异、`source_request` 类别和请求耗时；对照 DBA 提供的执行计划／扫描统计，分别记录分区裁剪、实际扫描、超时和失败原因。有失败先定位，不自动换账号、放宽上限或重跑。脚本不注入断连，`historical_stream_failure` 固定为 `not_tested`。故障需在另获批准的隔离环境复现并核对失效后新增业务源 dispatch 为 0；未复现则记「待验证」，不得声称修复。

## 3. 兼容通过后才开始正式 A/B 和试用

1. **冻结题册和评分。** 20 道高频指标、15 道跨表、10 道口径歧义／证据不足、5 道故障恢复。每题提前标注应回答、应澄清或应阻断、正确口径／数值／证据、是否高风险及是否属于已建模常见问题。至少有重复事实、跨租户同 ID、漏配维表、UTC 日界、零分母、截断和关停场景。兼容性清单里的构造题不是这 50 道实测题。
2. **各跑至少 150 次。** 两版用相同模型、预算、时区、权限、数据与数据水位；每题每版至少 3 次，交错运行两版。冷／热、首次提问／本地追问分组；独立新会话，追问和恢复题按题册重建初始状态。记录 `case_id`、版本、轮次、场景、最终状态、首条业务 SQL 执行结果、首个可核验答案耗时、操作数证据、各类驱动 dispatch。旧版用同一驱动边界计量，不从历史工具调用推断；无法采集标「缺失」，不能按 0。
3. **按预先约定的组出结论。** 可回答题的口径、数值和证据全对率 ≥95%（无理由弃答计错）；高风险错误标「已核验」0 次；已建模常见题首条业务 SQL 可执行率 ≥95%（应查询却未发 SQL 计失败）；同组从提问到首个可核验答案的 P90 降低 ≥40%。按各组最近秩 `ceil(0.90 × n)` 算 P90，无可核验答案计为未在时限内完成，不从样本里剔除；若 P90 落到未完成、任一侧无可比值或计量缺失，不宣称 P90 达标。分别报告失败／超时／弃答和模型等待、预检、源库、核验、本地计算，附样本数及独立评分复核。
4. **人测与回切。** 至少 5 人完成查找分母、原始结果和图表的试用，记录耗时／点击及问题；实机手机与本机移动视口分别标注。兼容性、A/B、试用及业务签认均有记录后，才由授权人按连接启用。异常时先关闭该连接的开关，确认新任务回探索模式、旧报告和旧证据仍读得出；不要用新公式改写旧结果。
